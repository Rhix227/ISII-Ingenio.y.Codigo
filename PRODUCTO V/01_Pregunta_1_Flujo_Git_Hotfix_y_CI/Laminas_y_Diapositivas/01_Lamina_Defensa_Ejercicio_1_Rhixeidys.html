⚡ 1. Comandos Git ante Incidente
1. Pausar Feature PDF
Guarda el trabajo local en curso sin ensuciar el árbol.
git stash push -m "wip: pdf export"
2. Aislar y Resolver Hotfix
Actualiza main y crea la rama de emergencia.
git checkout main && git pull
git checkout -b hotfix/login-bug
3. Publicar y Desplegar Hotfix
Commit del parche y envío a PR de producción.
git commit -m "fix(auth): login" && git push
4. Sincronizar y Evitar Merge Hell
Rebase lineal del hotfix sobre la feature y recuperar stash.
git checkout feature/pdf-export
git rebase origin/main && git stash pop
📋 2. Plantilla de Pull Request
Descripción Técnica:
Detalle arquitectónico del endpoint /api/facturas/:id/pdf y librería seleccionada.
Evaluación de Impacto:
Consumo de memoria en V8 por streams y blindaje contra inyección de datos dinámicos.
Checklist de Revisión Humana:
✓ ¿Se incluyeron pruebas unitarias para generación de PDF?
✓ ¿Se auditaron dependencias de terceros contra CVEs?
✓ ¿Se validó ejecución como usuario no-root en Docker?
🛡️ 3. Quality Gates de CI
Gate 1: Integridad Lógica npm test
Ejecución automática de pruebas unitarias con cobertura mínima del 80%. Si una prueba falla, bloquea el merge.
Gate 2: Calidad Arquitectónica SAST / Sonar
Análisis estático de código para detectar code smells, duplicación y deuda técnica. Bloquea código defectuoso.
Gate 3: DevSecOps (SCA) npm audit
Escaneo de composición de software. Bloquea el merge si la librería PDF tiene vulnerabilidades severas o críticas.
Árbitro Algorítmico: Merge bloqueado hasta aprobación total
